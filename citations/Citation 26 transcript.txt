#include <queue>
#include <nav_msgs/msg/path.hpp>
#include <geometry_msgs/msg/pose_stamped.hpp>

// Given: std::queue<geometry_msgs::msg::PoseStamped> pose_queue

nav_msgs::msg::Path path;
path.header.stamp = this->now();
path.header.frame_id = "map"; // or whatever your fixed frame is

// Copy queue since std::queue doesn't support iteration
auto q_copy = pose_queue;
while (!q_copy.empty()) {
    path.poses.push_back(q_copy.front());
    q_copy.pop();
}

A few notes:

    nav_msgs/msg/Path just wraps a std_msgs/Header + vector<PoseStamped>, so you're essentially draining the queue into that vector.
    The path.header.frame_id should match the frame used in your PoseStamped messages (e.g. "map" or "odom").
    If you want to avoid copying the queue, consider storing your poses in a std::deque instead — it supports iteration directly, so you can do path.poses = std::vector<...>(pose_deque.begin(), pose_deque.end()).

Is there a better data structure for storing my poses? I want the queue-like properties of being able to push to the front and pop from the back, while easily providing it as the poses field of the path message
4:22 PM
Weighed deque versus vector for dual-end queue operations

std::deque is the ideal fit here:

    O(1) push/pop at both ends (push_front, push_back, pop_front, pop_back)
    Supports iteration, so you can assign to path.poses in one line

cpp

#include <deque>

std::deque<geometry_msgs::msg::PoseStamped> pose_deque;

// ... push/pop as needed
pose_deque.push_back(new_pose);
pose_deque.pop_front();

// Assign directly to path
nav_msgs::msg::Path path;
path.header.stamp = this->now();
path.header.frame_id = "map";
path.poses.assign(pose_deque.begin(), pose_deque.end());

If you don't actually need push-to-front and only ever append, a plain std::vector is even simpler since path.poses is a std::vector — you could just assign it directly:
cpp

path.poses = my_pose_vector;

But for true double-ended queue semantics with clean Path conversion, std::deque is the right call.

pose_deque.push_back(current_pose);

That's it — push_back adds to the back, pop_front removes the oldest entry from the front, keeping it a sliding window of your most recent bot_path_length poses.

std::deque::size() returns size_t, so casting the parameter to size_t is the cleanest match. Alternatively you can store it as a member variable:
cpp

size_t bot_path_length_ = static_cast<size_t>(get_parameter("bot_path_length").as_int());

Then your comparison stays warning-free:
cpp
